    The feedback link

    Feedback filled in on a phone, or on any machine without the data folder, waits at the endpoint until this machine collects it. That needs a second key — MR_FEEDBACK_KEY in Script Properties — which submits feedback and can do nothing else. It is the one that travels; the key above never leaves this device.

    Anyone with the link can send feedback and read nothing. If you paste MR_KEY here by mistake you have handed out the roster, so do not.

    The code for the deck

    Put this on a slide in the presenter template once and leave it there. It carries the endpoint and the feedback key, so a phone that scans it can send feedback without anybody typing a URL. It keeps working until you change the feedback key — change that and come back here for a new one.

    Why the roster is not in this repository This site is public. Everything committed to it is served to anyone who asks, and a password on the pages would not change that — the JSON would be its own URL. So the roster lives behind this endpoint instead, and the pages stay public and empty. The endpoint holds who is on service and who was drawn; it never holds a score.

    Setting up the sheet

    1. Create a Google Sheet, then Extensions → Apps Script.
    2. Paste in morning-report/server/Code.gs from this repository and save.
    3. Run setUpSheets() once from the editor and grant the permissions it asks for. Four tabs appear: Roster, Rota, Sites and Draws — the last one fills itself in when a draw is confirmed.
    4. Project Settings → Script Properties, add MR_KEY with a long random string. Without it the endpoint refuses everyone, including you.
    5. Deploy → New deployment → Web app, execute as Me, access Anyone. "Anyone" is what lets a browser reach it at all; MR_KEY is the gate. Copy the /exec URL.
    6. Paste the URL and key above, then use Publish to fill the sheet from the data folder you already have.

    After that, a chief edits the Rota tab — one cell per task per day, names written as they appear on the Roster tab, two people separated by a semicolon — and every browser picks it up on the next load. Swaps and sick calls do not need anyone to re-export anything. Commas and surname-first names are understood too, since that is what a pasted QGenda cell looks like; anything unrecognised is listed above rather than silently dropped.
