What the code points at

The round is named here, once, by whoever hands the link out — rather than twenty times by twenty people typing it from memory. Which of the four groups somebody is in is the one thing the link never sets: that is theirs to tap.

Goes in the link and into every response, and is what a later round gets compared against.

Where to put it

The code is the same wherever it goes; what changes is how long somebody has to look at it.

  • On the last slide of report. The PNG at this size stays crisp on a projector. Leave it up while people are standing rather than flashing it at the end.
  • Taped in the workroom. Print this sheet — everything but the code and the address drops away on paper.
  • In a message. Send the address; it is short enough to read out loud, and nobody has to scan anything.

Whichever way it goes out, the denominator goes with it: the read-out can count responses and can never know how many people were asked. Note that number down when you hand the code round, or the percentage cannot be worked out later.

The key that may be in this link A phone cannot write to the facilitator's laptop, so a response filled in on one has to go to the collection point. The link carries the submit key that lets it — the weak key, which can put a response in and can read nothing back, not the roster key.

It is still a key. A printed copy of this code is a printed copy of that key, so treat the sheet the way you would treat the key itself, and set a new one in settings if a copy goes somewhere it should not have.
